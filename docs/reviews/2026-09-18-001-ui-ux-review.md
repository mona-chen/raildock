# UI/UX review — RailDock frontend

Date: 2026-09-18
Scope: `app/` (React 19 + Vite, TypeScript, Tailwind, shadcn/ui). Read-only review of
routing/navigation, the project canvas + service panel, settings, and the shared
component layer. No code changes were made as part of this review.

Findings are ordered by impact. Every claim is anchored to a `file:line`.

## Highest impact

### Errors masquerade as empty states
Only `ServicePanel` and the Updates tab of `SettingsPage` branch on `isError`.
`ProjectsPage.tsx:14`, `ServerPage.tsx:15`, `ActivityPage.tsx:41` and
`ProjectCanvas.tsx:77` destructure `{ data = [], isLoading }` and nothing else, so a
failed request renders "No projects found" / "No activity yet" — the user is told they
have nothing instead of that loading failed. React Query already retries twice, so
these are genuine dead ends with no retry affordance.

### Secondary text fails WCAG AA almost everywhere
Measured against the canvas background `#0b0b0d`:

| token / class | value | contrast | verdict |
| --- | --- | --- | --- |
| `--text-disabled` | `#4A4A55` (162 uses) | 2.25:1 | fail |
| `text-white/30` | `#545456` | 2.60:1 | fail |
| `--text-muted` | `#6B6B7B` | 3.76:1 | fail (normal text) |
| `text-white/40` | `#6D6D6E` | 3.80:1 | fail (normal text) |
| `--accent-purple` | `#8B5CF6` | 4.64:1 | pass |
| `--text-secondary` | `#A0A0B0` | 7.63:1 | pass |

These are form labels, empty-state copy and card sublabels. Raising the gray ramp
(disabled → `#6b6b7b`, `white/30` → `white/50`) fixes a large swath at once.

### Two parallel theming systems, and 93 hardcoded hexes
`index.css:9` defines a full token set plus `.btn-*` / `.card-dark` / `.input-dark` /
`.badge-*` classes, and `tailwind.config.js:50` defines the `rail.*` colors — but
components hardcode inline values instead: 93 distinct 6-digit hexes in TSX, including
12 near-identical "almost black" surfaces (`#0b0b0d`, `#0f0f13`, `#111114`, `#131318`,
`#16161a`, `#161618`, `#17171b`, `#18181b`, `#19191d`, `#1a1a1e`, `#1a1a1f`). Hover
purple is `#7c4fe0` in `StorageTab.tsx:238`, `SnapshotsSubTab.tsx:120`,
`BackupsSubTab.tsx:182` and `AddServiceModal.tsx:419` while the token is `#7C3AED`.
Collapsing onto the tokens is the single biggest visual-cohesion win.

### Modal/overlay layer is fragmented and under-accessible
24 hand-rolled `fixed inset-0` overlays across 18 files, but only 6 declare
`role="dialog"`/`aria-modal` and only 4 handle Escape. shadcn `dialog`,
`alert-dialog`, `sheet` and `drawer` ship in the repo and are used in just 5 files.
Focus trapping, scroll lock, Escape and ARIA therefore vary per screen, and stacking
relies on ad-hoc z-indexes (`z-50`×32, `z-[60]`, `z-[70]`, `z-[90]`×6, `z-[100]`×4).

### Destructive actions use native `window.confirm()`
`MembersTab.tsx:119`, `GitSourcesTab.tsx:484,538`, `BackupDestinationsTab.tsx:312`,
`DomainsTab.tsx:177`, `SettingsPage.tsx:232,644,800`, `ServerPage.tsx:218`. Blocking,
unbrandable, no impact detail — and inconsistent with the typed-name confirmations
already built for projects (`ProjectsPage.tsx`) and services (`SettingsPanel.tsx`).

## Navigation & information architecture

- **Primary nav is icon-only.** `IconRail.tsx:16` defines `NAV_ITEMS` with no text
  labels, only `title` tooltips. Projects/Servers/Activity/Platform are
  indistinguishable until hover, and tooltips do not exist on touch. "Platform" for
  what users think of as Settings is also non-obvious.
- **No 404 / catch-all route.** `App.tsx:39-47` defines no `path="*"`, so an unknown
  URL or stale bookmark renders a blank dark page.
- **Service panel is not deep-linkable.** Selection lives in a Zustand store
  (`stores/useCanvasStore.ts`), not the URL. You cannot share a link to a service,
  refreshing drops the open panel, and browser Back leaves the project instead of
  closing the panel. Filter/search/zoom are likewise unpersisted.
- **Settings IA mixes scopes.** `SettingsPage.tsx:38` presents 8 flat tabs where 5 are
  org-scoped (Organizations, Members, Git Sources, Backups, Deploy Keys) and 3 are
  instance-scoped (Integrations, Email, Updates), under a "Platform Settings" title.
  The `icon` field in `TABS` is declared but never rendered (`SettingsPage.tsx:64`
  renders only `tab.label`), and unlike `ServicePanel` the row has no `overflow-x-auto`.
- **No global search or command palette.** `components/ui/command.tsx` (a full cmdk
  palette) is imported nowhere; the only search is the local filter at
  `ProjectsPage.tsx:64`. `components/ui/breadcrumb.tsx` is also unused, so there is no
  location context past the project tab bar.

## Feedback & interaction

- **Settings auto-save fires per keystroke and toasts every time.**
  `SettingsPanel.tsx:107` calls `setConfigPath` on every `onChange`, and
  `hooks/useServices.ts:74` shows `toast.success('Settings synced to Dokku')` per
  mutation with no debounce and no optimistic update. Typing a 4-char publish directory
  is ~4 requests and ~4 toasts, and the input value is bound to the server-refetched
  `svc.config`, so it can rewind on a slow link. This affects the static-site fields
  added in `docs/plans/2026-09-18-001-fix-static-site-deploys-plan.md`.
- **Same status renders three different ways.** `ServiceCard.tsx:164` maps status to
  Title Case with a color; `OverviewTab.tsx:50` and `ServicePanel.tsx:220` do
  `status === 'running' ? 'Online' : status`, so a failing service reads "error" in one
  place and "Error" in another, and badge colors are not shared. Belongs in one
  `statusMeta()` helper.
- **Search-empty state lies.** `ProjectsPage.tsx:90-97` shows "No projects found" plus
  a "Create your first project" button whenever the filter matches nothing — even when
  the user already has projects and simply mistyped a query.
- **Keyboard help is out of sync.** `ProjectCanvas.tsx:385` binds `D` to a toast that
  never deploys on a second press ("Press D again to deploy — or use the Deploy tab"),
  and `?` toggles help, but neither `D` nor `?` is listed in the shortcuts panel
  (`ProjectCanvas.tsx:631`).
- **App-level ErrorBoundary is all-or-nothing.** `App.tsx` wraps every route in a single
  boundary, so any render error blanks the whole dashboard; `ErrorBoundary.tsx` also
  falls back to a 💥 emoji, off-style with the lucide icon system.

## Smaller polish

- `components/ui/tooltip.tsx` is unused while there are 92 native `title=` attributes;
  native tooltips are slow, unstyled and invisible on touch.
- `AuthGuard.tsx` hand-rolls a `border-2 animate-spin` spinner although
  `components/ui/spinner.tsx` exists.
- `ServicePanel.tsx:121` places the `database` tab after `console`, well past `data`.
- Mobile/tablet is not addressed: the icon rail and the `max-w-[800px]` service panel
  are fixed, and only `SettingsPanel.tsx` and `ProjectsPage.tsx` use `md:`/`lg:`.
- `AddServiceModal.tsx` discovery preview shows name/category/root dir and a builder
  override, but not the detected `publish_directory`, so the static-site decision made
  at import time is invisible and uneditable.

## Suggested first moves

1. Error states with retry on the four list/canvas pages.
2. Debounce + optimistic config updates; drop the per-keystroke toast.
3. Raise the gray ramp for contrast and collapse the hex sprawl onto the tokens.
4. Replace native `confirm()` with the typed, impact-aware dialog used elsewhere.
5. Add a `path="*"` route and URL-sync the active service panel.
