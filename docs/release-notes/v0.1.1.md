HTTP analytics can now set up its own access logging on a Traefik proxy, with a reviewed plan, a private backup and automatic rollback — instead of only reading logs someone else configured.

### Highlights

- **Reviewed proxy logging setup.** From **Servers → a server → HTTP traffic → Set up HTTP analytics**, RailDock can configure access logging on a root-running, CLI-configured Traefik container owned by a single Docker Compose file — including external Coolify proxies and Dokku's managed Traefik. Discovery is read-only, and Compose contents or secrets never reach the browser.
- **The review is signed and re-checked.** A 15-minute token binds the server, container identity and configuration digest. Host changes invalidate it, and the live configuration is verified again before anything is written.
- **Setup survives disconnects.** The write runs in a host-owned systemd unit with a private backup of the original Compose file, so it continues if RailDock or SSH goes away, and the result reconciles on the next visit. A failed startup restores the original configuration and recreates the proxy; a failed rollback is reported explicitly.
- **Logging never carries paths, IPs or headers.** The proxy keeps StartUTC, RequestHost, DownstreamStatus, DownstreamContentSize and Duration, buffered asynchronously and rotated hourly at 25 MiB with two backups.

### Security

- **puma 8.0.3** fixes seven advisories affecting 8.0.2: `pumactl` not verifying TLS identity, `ssl_cipher_filter` decoding `+` into a wider cipher list, graceful shutdown hanging on trickled bodies, and several reactor and accept-loop stalls. The dependency is now bounded to `~> 8.0.3`.

### Fixes

- Dokku setup uses the native `traefik-template-source` hook so logging survives template regeneration; an existing third-party hook is refused rather than overwritten.

### Limits worth knowing

- Applications behind the proxy may briefly lose connections while it is recreated, and startup checks do not verify every application route.
- Python 3, Docker Compose, systemd and logrotate must already be installed; nothing is installed automatically.
- External managers can later overwrite their own Compose source, and RailDock does not silently fight them — detect and review again if logging is lost.
- Log files can exceed 25 MiB between hourly checks, and disabling collection stops ingestion, not proxy logging or rotation.
- Manual recovery is documented in `docs/http-analytics.md`.

### Tests

- CI now runs the proxy setup and rollback suite (`test/http-setup`) alongside the Rails suite.
