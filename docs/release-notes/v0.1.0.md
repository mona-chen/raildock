First stable release. It brings honest observability — analytics, monitoring notifications and live host detail — plus release-channel and backup-safety fixes that had accumulated on `main`.

### Highlights

- **HTTP analytics, opt-in.** RailDock reads your existing Traefik or Caddy JSON access logs rather than reconfiguring the proxy. Only aggregate counts are stored: no query strings, client IPs, headers or bodies, and path persistence is off by default. Backlog, malformed lines and log-rotation gaps are reported instead of being papered over.
- **Configurable monitoring notifications.** Organization-level policies with sustained thresholds, deduplication and SMTP delivery, on their own queue so a slow mail server cannot starve deployments or backups.
- **Live host detail.** `/dashboard/servers/:serverId` is a full page with resources and HTTP tabs, real capacity (logical cores, used/total/available memory and storage) and coalesced collection that keeps SSH outside the database transaction.
- **Settings → Observability.** Host and application metric collection can be disabled independently, retention is configurable (1–90 days), and disabling collection preserves existing history until it expires.

### New features

- **HTTP analytics** from Traefik/Caddy access logs, limited to a 2 MiB read budget per pass with bounded path cardinality.
- **Minute and hourly rollups.** Minute detail expires after at most two days; hourly retention is configurable from 1–30 days, and longer dashboard windows read the hourly aggregates. Latency histogram counts are merged before percentile bounds are calculated.
- **Application and host metric history**, with failures recorded as unavailable rather than zero.
- **Release channels.** Versioned installations check stable releases; development installations track `edge`.

### Fixes

- Host updates are detached from the request that schedules them, so the API returns `202` for accepted work and the UI reports host progress or rollback instead of blocking on its own replacement.
- Deployment logs carry clearer failure context.
- Application metric history no longer loses or misattributes samples.

### Security

- **Lockbox 2.3.0** (GHSA-586r-mm5q-xhg2, insecure hybrid cryptography). RailDock never uses hybrid mode — `Server`, `OrganizationSshKey` and `DokkuEngine` each build a plain AES-256-GCM box — so the affected path was unreachable. Existing encrypted values stay readable; no re-encryption is needed.
- **MessagePack 1.8.7** (CVE-2026-126366), precautionary: it arrives only through bootsnap and the advisory is specific to the JRuby decoder.

### Tests

- A compatibility spec decrypts an AES-256-GCM fixture written before the Lockbox upgrade, confirming existing rows survive it.
- The GitHub App callback spec no longer depends on the host environment's `APP_URL`, so it passes locally and in CI alike.
