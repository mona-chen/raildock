The project canvas can now show measured traffic between linked services, and HTTP analytics can retain request paths when you explicitly opt in — including on the logging RailDock sets up for you.

### Highlights

- **Measured service connections.** Turn on **Servers → a server → Service connections** to sample direct TCP traffic between linked services on that host. RailDock reads Linux `TCP_INFO` socket counters through `nsenter`/`ss`; no agent, packet capture, firewall rule, sysctl or application instrumentation is installed. It is off by default.
- **The canvas shows direction, not just activity.** A pulse means the byte counter rose in the last sample: outbound traffic travels toward the target, return traffic comes back. Unselected connections stay muted so emphasis follows selection. Selecting one shows its counters, when it was last observed and any retained minute history.
- **Animation and collection are separate decisions.** The canvas control governs movement only; reduced-motion preferences and hidden tabs stop it, and motion is capped at 40 connections while every other connection still reports counters. Collection is switched per server, and disabling it stops host sampling entirely.
- **Traffic history is opt-in.** **Live only** keeps the latest snapshot and writes no history. Retaining 1–30 days of minute aggregates grows storage with the number of links; shortening retention prunes older rows, and cleanup keeps running while collection is off.
- **Request paths are now a reviewed choice.** Automatic logging setup keeps five fields and drops everything else. Switching on **Retain normalized request paths** before the review adds `RequestPath` — the only field that can carry user data to disk — and the review states it. Collection then keeps up to 25 normalized categories per bucket, collapsing identifier-like segments to `/:id` and grouping the rest as `(other paths)`.
- **Changing that choice goes back through review.** Flipping it rewrites the proxy configuration, so it needs a new signed review and one proxy restart. The settings endpoint refuses a silent change on automatically configured logging rather than reporting retention the log file cannot provide; manually connected sources keep the direct toggle.

### Fixes

- Flow sampling now waits for staged SSH host keys to settle before locking a snapshot, so a newly accepted host key no longer fails the first collection.

### Limits worth knowing

- This is sampled TCP visibility, not a flow ledger. Connections that open and close between samples can be missed, and UDP, Unix sockets, host networking, indirect proxy/NAT paths and ambiguous container mappings are not covered. Missing permissions or tools report unavailable telemetry, not measured zero; an idle socket is not a broken one.
- Collection requires root SSH, Linux 5+, Python 3, `nsenter` and a modern `ss`. Sampling runs every minute in the background and about every 10 seconds while a canvas is open; samples older than 25 seconds never animate. Work is bounded per host (32 source containers, 500 links, 10,000 socket counters, four MiB of output, eight seconds of traversal).
- Retained paths can contain sensitive identifiers. Enabling retention writes them to the root-private proxy log before RailDock reduces them to bounded categories; query strings, client IPs, headers and bodies are never retained.
- Turning path retention on or off restarts the proxy once, so applications behind it may briefly lose connections.
- See `docs/network-flow-observability.md` and `docs/http-analytics.md` for the measurement and recovery details.

### Tests

- A host-side suite covers the flow collector's parsing, baselines and budgets (`test/network-flows`), and canvas tests cover pulse direction, staleness and the motion cap.
- The proxy setup suite now asserts that `RequestPath` is kept only when the reviewed plan opts in.
