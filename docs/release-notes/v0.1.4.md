RailDock now has a token-scoped API for agents, an MCP endpoint your assistant can connect to, and profile editing for both people and organizations.

### Highlights

- **Agent API tokens.** Create a token in **Settings → Agent Access** with a project or environment binding and a narrow set of scopes: `read`, `deploy`, `config:write` and `destructive`. The secret is shown once, only a SHA-256 digest is stored, and revoking never deletes the audit row. Tokens act as a delegated user, so the member's role still applies.
- **A read-only `/api/v1` surface.** `context`, `projects`, `services`, logs and diagnosis are presenter-shaped for agents. Environment variable values, config values, SSH keys and webhook tokens are never serialized; callers get names and `webhook_configured` instead.
- **Review before apply.** `POST /api/v1/plans` returns a signed, 15-minute plan carrying the exact manifest, its base digest and the services it would remove. Applying a stale plan fails with `409 plan_drifted`; removals require the reviewed removal token and the `destructive` scope.
- **Operations and idempotent writes.** Deploy, restart, rollback and plan applies return an operation you can poll. Deploy and restart require an `Idempotency-Key`; repeating one returns the original operation and starts no second deployment. Status is derived from the deployment or manifest operation, never copied.
- **MCP transport.** `POST /mcp` speaks Streamable HTTP JSON-RPC and exposes ten tools: context, service reads, diagnosis, logs, plan/apply, operation polling, deploy and rollback. It composes the same scope, binding and authorization checks as the REST API, so a tool cannot bypass them.
- **Per-token rate limits and an OpenAPI contract.** Both surfaces share a 120-request/minute budget per token with `Retry-After`. `GET /api/v1/openapi` and the `raildock://openapi` MCP resource serve the OpenAPI 3.1 document, and `docs/agents-api.md` documents authentication, error codes, the 428 flow and redaction guarantees.
- **Edit your profile.** **Settings → Profile** updates your name, email and password. Changing your email or password requires your current password, and API tokens are refused: a leaked agent credential cannot take over the account. The sidebar user row links straight to it.
- **Edit an organization profile.** Owners and admins can change an organization's name, slug and avatar from **Settings → Organizations**, with a live preview and duplicate-slug errors. Only owners can delete.
- **Reliability fixes.** Agent deploys and rollbacks no longer fail before enqueueing (Solid Queue's concurrency key rejected the extra audit argument), and a manifest generated from live state now plans as a true no-op instead of reporting its own defaults as drift.

### Also in this release

- The Tailwind CSS v4 build is in place.
- Host updates back up the actual RailDock database with the bundled PostgreSQL client that matches the running server.
- CI now runs on the new `develop` integration branch; `main` remains the release branch, so feature work can land without publishing an edge image.

### Limits worth knowing

- Tokens are delegated users, not a separate permission system. A token can never exceed its owner's role, and email/password changes still require the person's current password.
- `/api/v1` does not yet expose bulk project deploys or project deletion; use the dashboard for those. The dashboard deletion protocol and its typed confirmation are unchanged.
- Diagnosis reads stored deployments, metrics and activity and performs no SSH. Missing samples are reported as unavailable, never as zero. Logs fall back to stored deployment logs with an explicit reason when the host is unreachable.
- Per-token rate limiting disables itself if the shared cache is unavailable rather than failing requests.

### Tests

- Full suites: 1651 backend examples and 183 frontend tests.
- A live Docker smoke test drove the MCP endpoint end to end: initialize, tools, context, service reads, diagnosis, logs, plan/apply, operations, deploy/rollback, resources, scope denial, project binding, secrets redaction and rate limiting.
- The deploy/rollback enqueue bug and the manifest round-trip regression were both found by that live test and covered by regression specs.
